## 1. ما تم فحصه وما لم يتم فحصه

هذه الجلسة تعمل على جهاز سحابي منفصل، ولا تستطيع الوصول إلى جهاز اللابتوب القديم مباشرة. لذلك تم العمل على جزأين:

| الجزء | الحالة |
|---|---|
| فحص المشاريع المرفوعة على GitHub (قراءة فقط) | ✅ تم: 9 من 10 مستودعات |
| مستودع check-reminder | ❌ لم يُفحص: لم يُمنح إذن الوصول في هذه الجلسة |
| فحص الجهاز القديم نفسه | ⏳ معلّق: يحتاج تشغيل سكربت الفحص على الجهاز |

السكربت المرفق يقرأ فقط ولا يغيّر شيئًا على الجهاز:

- `Audit-OldLaptop.ps1`
- `Run-Audit.cmd`

طريقة تشغيله موجودة في القسم 9.

## 2. الملخص التنفيذي

1. معظم الأنظمة الإنتاجية تعمل في السحابة، ولن تتأثر بتغيير الجهاز طالما لم نعد إعدادها مرتين.
2. يوجد نظام دفع آلي لبيانات الربحية لا يوجد كوده في أي مستودع، ويُرجّح أنه يعمل من الجهاز القديم. هذا أهم بند في النقل.
3. توجد ملفات مهمة لا يحفظها GitHub أصلًا، مثل ملفات الأسرار وملفات البيانات المحلية وإعدادات النشر.
4. أي سكربت لتركيب المنبّهات أو أي استيراد جديد لمسارات العمل الآلية قد يسبب تكرار العمليات، لذلك يجب ألا يُعاد تشغيله أثناء النقل.
5. المشروعان القديمان من النسخة الأولى يبدوان متوقفين ويحتاجان تأكيدك.

**دفع حزم Monte و Amman (غير معروف المكان)**

الخادم يستقبل حزمتين آليًا، لكن الكود الذي يرسلهما غير موجود في أي مستودع. يوجد في ملف اختبار مسار يشير إلى مجلد محلي على الجهاز:

```
C:\x\_PMS\monte_pms.json
```

الخادم يتجاهل الحزمة المطابقة ويرفض الحزمة الأقدم، لكنه لا يمنع حزمة أحدث تاريخًا مبنية على ملفات قديمة. لو بقي الجهاز القديم يعمل بعد النقل، قد يكتب بيانات قديمة فوق الصحيحة.

## 6. ما لا يحفظه GitHub

هذه العناصر تحتاج نسخًا مستقلًا، ولا يكفي رفع الكود:

- ملفات `.env` لكل خادم
- ملفات البيانات المحلية (xlsx, csv, msg, pdf)
- ملفات clasp
- أي تعديلات غير مرفوعة أو فروع محلية أو Stash
- إعدادات Claude Desktop و Claude Code و MCP Servers و Skills
- مفاتيح SSH وإعدادات Git
- ملفات QuickBooks أو Outlook إن وُجدت

## 9. الخطوة المطلوبة منك: تشغيل الفحص على الجهاز القديم

السكربت يقرأ فقط. لا يحذف ولا يعدّل ولا يوقف ولا يفعّل أي شيء، ويكتب نتائجه في مجلد جديد على سطح المكتب فقط.

1. انسخ المجلد `migration-audit` إلى الجهاز القديم.
2. اضغط مرتين على الملف `Run-Audit.cmd` (كمستخدم عادي أولًا).
3. انتظر حتى تظهر رسالة الانتهاء باللون الأخضر.
4. ستجد مجلدًا جديدًا على سطح المكتب يبدأ اسمه بالكلمة `MIGRATION_AUDIT_`.

داخل مجلد النتائج:

| المجلد | المحتوى | هل يمكن مشاركته؟ |
|---|---|---|
| SHAREABLE | جداول مع إخفاء الأسرار | نعم، بعد نظرة سريعة منك |
| PRIVATE_DO_NOT_UPLOAD | نسخ XML الكاملة للمهام المجدولة | لا. يبقى عندك فقط |
| audit_log.txt | سجل التشغيل والأخطاء | نعم |

لو فيه مشاريع على قرص آخر أو مجلد غير معتاد، شغّل السكربت بهذا الشكل:

```
Run-Audit.cmd -ExtraRoots "D:\Work","E:\Archive"
```

طريقة الإرسال الأسهل والأكثر أمانًا هي فتح Claude Code على الجهاز القديم نفسه داخل مجلد النتائج، وإكمال التقرير من هناك.
